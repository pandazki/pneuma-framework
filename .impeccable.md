# Impeccable Design Context — clean-room production example

Scope: the two browser surfaces of the clean-room production example
(`examples/clean-room-release-host` and `examples/clean-room-release-board`).
This is a capability-boundary reference example, not a throwaway demo. The bar
is "this delights and looks deliberately made," not "it works."

A core requirement: the two surfaces must be visually distinct so a viewer
instantly knows which framework layer they are looking at — the **Builder**
governing the app (Creation Host) vs the **End User** using the app (Published
Application). The chosen lever is theme polarity: a light operational console
for the Host, a dark editorial deck for the App.

---

## Surface 1 — Creation Host (developer platform / control plane)

### Users
Developers and Builders operating a governed build → preview → evolve → approve
→ publish → rollback loop. Used in daylight, long focused sessions. They need
to trust the state they see and the evidence behind each transition.

### Brand Personality
Precise · governed · operational. A calm mission-control console, not a
marketing page. Confidence comes from legibility and structure, not decoration.

### Aesthetic Direction
Refined utilitarian / operational precision. **Light theme.** Neutrals tinted
toward cool slate (hue ~255). One confident primary (deep indigo) reserved for
the governed primary action; semantic state colors for lifecycle stages. The
signature element is the **lifecycle pipeline**: stages rendered as a legible
horizontal state machine with inline evidence receipts (version ids, checks,
deploy receipts) in monospace.

- Theme: light, cool-slate neutrals, never pure white/black.
- Type: Display = **Archivo**; Body/UI = **Hanken Grotesk**; Mono = **Spline Sans Mono** (ids, versions, receipts).
- Accent discipline: indigo primary is rare; most of the surface is neutral.

## Surface 2 — Generated Application (Release Operations Board)

### Users
Release managers and engineers tracking release items, risk, and SLA — often in
focused or on-call contexts. They want signal at a glance and a satisfying,
physical sense of moving work forward.

### Brand Personality
Kinetic · confident · operational. An ops "flight deck" with editorial weight.

### Aesthetic Direction
Editorial-industrial flight deck. **Dark theme.** Warm-charcoal neutrals (hue
~75), a restrained gold used as the structural/brand accent (NOT as a status
color), and a dedicated status hue system: queued = cool slate, in_progress =
amber, blocked = coral, shipped = green. Each release item is a substantial
typographic card; a cadence/timeline rail carries events; status transitions
feel deliberate and physical.

- Theme: dark, warm-charcoal neutrals, never pure black.
- Type: Display = **Bricolage Grotesque**; Body = **Figtree**; Mono = **Spline Sans Mono** (version / commit-like ids).
- Accent discipline: gold is structural punctuation; status hues carry meaning.

---

## Shared Design Principles

1. **Theme polarity encodes layer.** Light = governing (Host). Dark = using (App). Never blur the two.
2. **OKLCH everywhere**, neutrals tinted toward each surface's brand hue, chroma reduced near the extremes.
3. **Accent is rare.** 60-30-10 by visual weight; rare accents keep their power.
4. **Evidence is typographic.** Ids, versions, receipts, and checks read as deliberate monospace data, not afterthoughts.
5. **No AI-slop tells.** No left/right accent stripes >1px, no gradient text, no glassmorphism-by-default, no identical card grids, no centered-everything, no monospace-as-"technical" shorthand.
6. **Motion is one orchestrated moment, not scattered twitches.** Transform/opacity only; ease-out (quart/quint); respect reduced-motion.
7. **Every state designed.** Empty states teach; loading, error, and overflow are intentional.
