# Milestone 17 Snapshot: Security + Architecture Acceptance Gate

**Date:** 2026-05-04
**Status:** Closed after security fixes, architecture acceptance, lifecycle ADR, integration boundary cleanup, and regression verification
**Audience:** teammates with zero Pneuma context
**Scope:** what M17 fixed, what model decisions are now accepted, and why the next milestone is open-ended app pressure before release-candidate review.
**Chinese version:** [Milestone 17 Snapshot zh-CN](./milestone-17-snapshot.zh-CN.md)

## Executive Summary

M16 showed that Pneuma now has a coherent Reference Creation Host:

```text
Developer configures a Creation Host
  -> Builder creates and evolves Generated Applications
  -> Builder publishes, monitors, restarts, and rolls back Published Applications
```

M17 did not add a product feature. It asked a harder release-readiness question:

> Are there any security or architecture issues that would make a release-candidate review misleading?

The answer was yes, and M17 closed the critical ones:

- external HTTP callers can no longer spoof the reserved `framework` identity;
- framework lifecycle calls now use a private internal runtime token;
- query Operation and View source invocation checks fail closed by default;
- rollback now records durable failure evidence after the pre-rollback backup;
- ADR-0029 and the four-artifact model are explicitly accepted;
- lifecycle is pinned as a runtime subsystem in ADR-0030;
- Linear/OpenRouter packages are marked as reference integrations, not framework core semantics.

M17 also surfaced one important legacy assumption: Priority Queue used to rely on public query defaults. The capability proposal now includes both explicit `invoke operation:list_priority_queue` and `read view:priority_queue` policies.

## Accepted Architecture

M17 explicitly accepts this model:

```text
pneuma-framework
  -> Creation Host
  -> Generated Application
  -> Published Application
```

And this primitive boundary:

```text
Operation + definition-as-data is the core creation primitive.
Lifecycle scripts are a runtime subsystem behind semantic tools.
Concrete integrations are reference integrations unless promoted by ADR.
```

This matters because the project had drifted from the original v0 plan. That drift is now a deliberate accepted decision, not an accidental branch outcome.

## What Changed

| Area | Change |
|---|---|
| HTTP trust boundary | `x-pneuma-user-id: framework` is rejected unless paired with the runtime's internal token. |
| Lifecycle runtime calls | `PNEUMA_INTERNAL_HTTP_TOKEN` is generated by the framework and passed to child runtimes; internal definition calls send `x-pneuma-internal-token`. |
| Query policy default | GET/query Operation invocation now uses `resourceDefaultAccess: "restricted"` regardless of app default posture. |
| View visibility | Views only appear when both `read view:<id>` and `invoke operation:<source>` allow. |
| Rollback evidence | A mid-rollback failure after backup appends `definition_rollback_failed` with target version, backup version, error, recovery hint, and impact. |
| Architecture docs | Creation Host model now records the accepted M17 boundary and RC open-ended pressure requirement. |
| ADRs | Added ADR-0030 for lifecycle subsystem contract. |
| Integration packages | `adapter-linear` and `provider-openrouter` are private `reference-integration` packages. |
| Priority Queue proposal | Added explicit invoke policy and reordered per-mutation demo changes so View rediscovery stays fail-closed. |

## Security Findings Closed

| Finding | Risk before M17 | M17 closure |
|---|---|---|
| Framework identity spoofing | Any caller with HTTP access could set `x-pneuma-user-id: framework` and try to invoke internal definition/rollback operations. | Public HTTP rejects reserved framework identity without valid `x-pneuma-internal-token`; lifecycle-owned calls carry the private token. |
| Query GET defaulted through public posture | A missing policy rule could leak query-backed data when app default posture was public. | Query invoke checks fail closed with restricted default; tests cover anonymous GET without explicit policy. |
| View source invoke defaulted through public posture | A View could become visible when its source query Operation had no explicit invoke policy. | `/api/config.views` uses the same restricted invoke decision for source Operations. |
| Rollback half-failure opacity | A rollback failure after backup could leave mutation state hard to diagnose. | Failure evidence is appended as `definition_rollback_failed`; this is recovery evidence, not a cross-store transaction claim. |

## What Is Proven

| Claim | Evidence |
|---|---|
| Framework identity is no longer user-header spoofable | Runtime rejects reserved framework principal without internal token; lifecycle calls carry the token. |
| Query/View exposure is fail-closed | GET/query and `/api/config.views` now require explicit invoke permission. |
| Rollback failures are diagnosable | `definition_rollback_failed` history entry points to the pre-rollback backup. |
| The model replacement is accepted | Creation Host model and roadmap now record ADR-0029 + four-artifact acceptance. |
| Lifecycle is pinned without becoming the core primitive | ADR-0030 defines lifecycle semantic tools, env, markers, and internal token boundary as a subsystem. |
| Concrete integrations are not core semantics | Package metadata and docs mark Linear/OpenRouter as reference integrations. |
| Existing demos survived the stricter security posture | Priority Queue now declares invoke/read policies explicitly and M5/M6/M7/M13/M16 regressions pass. |

## What Is Not Proven

M17 does not claim:

- cross-store ACID rollback transactionality;
- hosted multi-tenant service identity beyond local internal token;
- production IAM, assignment, retention, or admin workflows;
- zero-downtime deploy or production traffic switching;
- arbitrary app generation;
- open-ended UI/code-heavy app creation;
- hot reload;
- stable Runtime Agent in published apps;
- full Pneuma 2.x dogfood coverage.

## Strategic Read

M17 is a gate, not a feature milestone. Its value is that it stops the project from walking into RC with two hidden problems:

```text
"enterprise security" with spoofable framework identity
"public app" behavior that accidentally exposes missing query policies
```

It also stops the architecture story from being ambiguous. The accepted story is now:

```text
Build applications through governed Operation semantics.
Use lifecycle as runtime plumbing.
Let Creation Hosts productize the builder experience.
Keep concrete vendors as reference integrations.
```

## Next Milestone

M18 should be **open-ended app pressure** before release-candidate review.

Knowledge Inbox and Team Decision Log are both schema-driven business apps. They are valuable, but too similar. Before M19 RC review, the framework needs a less structured pressure line: a webcraft-style app, UI/code-heavy generated surface, or equivalent open-ended creation path.

The question for M18:

> Does the four-artifact model and Operation-centered primitive story still hold when the generated app is not mainly a table/list/workflow product?

If yes, M19 can become a real release-candidate review. If no, M18 should expose the missing abstraction before the project locks itself into a narrow framework shape.
